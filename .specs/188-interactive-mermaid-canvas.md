# Spec 188 — Interactive Mermaid canvas

## Context

AI-generated diagrams can exceed the width and height available in chat, notes, and transcript
content. Horizontal scrolling alone does not let people inspect dense relationships or switch to a
focused workspace.

The canvas must provide predictable spatial navigation without interfering with page zoom or page
scrolling, and without weakening the protections applied to untrusted SVG content.

## Glossary

- **Canvas**: interactive area that presents a previously validated diagram.
- **Viewport**: the diagram's current scale and displacement inside the canvas.
- **Expanded view**: a focused dialog that occupies the usable viewport.
- **Pointer capture**: continuation of a drag gesture that started inside the canvas.

## Requirements

### Ubiquitous

- The system shall limit diagram scale to the inclusive range from 50% to 300%.
- The system shall present named controls for zooming in, zooming out, resetting, and expanding the
  view.
- The system shall provide canvas names and titles in Brazilian Portuguese and English.
- The system shall accept only SVG that passed the existing security validation.
- The system shall keep scripts, active content, external references, and unsafe CSS URLs out of the
  rendered SVG.
- The system shall allow the page to keep scrolling when the wheel is used without Ctrl or Cmd.

### Event-driven

- When a person activates zoom in or zoom out, the system shall change scale by 25 percentage points
  without exceeding the limits.
- When a person activates reset or presses `0`, the system shall return to 100% scale and remove all
  displacement.
- When the focused canvas receives `+` or `=`, the system shall zoom in and prevent the browser's
  default action.
- When the focused canvas receives `-`, the system shall zoom out and prevent the browser's default
  action.
- When a person uses Ctrl or Cmd with the wheel over the canvas, the system shall zoom only the
  diagram and prevent browser zoom.
- When a person uses the wheel without Ctrl or Cmd, the system shall not change diagram zoom or
  cancel the event.
- When a primary-button drag starts on the canvas, the system shall move the viewport according to
  pointer displacement.
- When the pointer ends, is cancelled, or loses capture, the system shall end the dragging state.
- When a person double-clicks the canvas, the system shall reset the viewport.
- When a person requests expansion, the system shall open a focused, near-full-screen view while
  preserving the current viewport.
- When the expanded view closes through its button, Escape, or an external action, the system shall
  end any active drag.

### State-driven

- While the diagram is being dragged, the system shall communicate the active drag through the
  cursor.
- While the scale is at its minimum or maximum, the system shall disable the corresponding zoom
  control.
- While the expanded view is open, the system shall keep an accessible title and a keyboard-accessible
  close control.
- While the canvas has focus, the system shall display a perceptible focus indicator.

### Optional

- Where a device provides touch or pen pointers, the system shall offer the same drag interaction as
  a mouse.

### Unwanted behavior

- If Mermaid rendering fails, then the system shall present the safe source as a fallback.
- If the SVG contains active content or an external reference, then the system shall reject the
  diagram.
- If a zoom attempt exceeds 50% or 300%, then the system shall retain the corresponding limit.
- If the view holding pointer capture unmounts, then the system shall clear the dragging state.
- If diagram content changes, then the system shall reset the viewport before interaction.

## Acceptance criteria

- [ ] Controls change scale in 25-point steps between 50% and 300%.
- [ ] Dragging works with mouse, touch, and pen, and ends on `pointerup`, cancellation, or capture
      loss.
- [ ] Ctrl/Cmd + wheel zooms the diagram without zooming the browser.
- [ ] Wheel input without a modifier preserves normal page scrolling.
- [ ] `+`, `=`, `-`, and `0` work with visible focus and cancel only their default actions.
- [ ] Double-click resets scale and displacement.
- [ ] Expansion opens an accessible near-full-screen dialog and preserves the viewport.
- [ ] Closing the dialog during a gesture does not leave the canvas in a dragging state.
- [ ] Changing the SVG resets the viewport.
- [ ] Strict sanitization and the safe fallback remain active.
- [ ] The interface and release note have parity between English and Brazilian Portuguese.

## Out of scope

- Visual Mermaid editing.
- Changing the Mermaid code generated by AI.
- Exporting a diagram as an image or PDF.
- Synchronizing the viewport across devices or sessions.
- Using the operating system's native fullscreen API.

## Risks and decisions

- Wheel events can be passive by default; acceptance requires verifiable cancellation.
- Very dense diagrams remain constrained by Mermaid renderer performance.
- The dialog preserves the current viewport instead of automatically fitting the diagram.

> 2026-08-10: non-passive wheel cancellation and capture-loss cleanup were formalized after an
> independent review of the initial prototype.
