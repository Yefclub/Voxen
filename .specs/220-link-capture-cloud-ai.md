# Spec 220 — Link capture and cloud AI interpretation (Product 2 as a Voxen extension)

## Context

On 2026-11-09 the owner reversed part of spec 215. Voxen again captures
links and interprets them with AI, as an extension of the same app (same
repository, database, login and UI). Inference runs only through cloud
model providers selected by the user. Voxen runs no local models, no
embeddings and no forecasting. Baseline `dev` at `0e5f74b`. Background
study (informative only, private):
https://claude.ai/artifact/63nthyW3iQirBsyv6ZKuU6. This spec is
self-contained and normative.

Production data that shaped the scope (306 documents, read-only aggregate):
X 44%, web 17%, YouTube 12%, TikTok 13%, uploads 13%. 26% of the library
(all TikToks) only became text through speech-to-text.

## Glossary

- Capture: turning a submitted link or file into text plus images, without AI.
- Interpretation: one structured AI call that produces title, summary, key
  points, tags and entities from captured text and images.
- Capture worker: the `capture-worker` container that runs yt-dlp, Deno,
  ffmpeg/ffprobe and Trafilatura. It holds no MASTER_KEY, no provider key
  and no database credentials; its only secret is `CAPTURE_WORKER_TOKEN`.
- Egress proxy: Smokescreen inside the capture worker. Every outbound
  request of the worker goes through it and it denies private, loopback,
  link-local and metadata address ranges.
- Provider: OpenAI, Anthropic, OpenRouter or xAI.
- Role: what a model is used for — `fast`, `standard`, `vision`, `stt`.
  Interpretation uses `standard` (falls back to `fast`).
- Capture artifact: the worker result for a job (text, segments, metadata,
  images), stored at `workspaces/<userId>/captures/<jobId>/capture.json` in
  the selected storage driver so a retry can skip downloading again.

## Decisions (closed)

- D1. Product 2 lives inside Voxen. Downloading and media processing run in
  a separate container; AI calls and keys stay in the web process.
- D2. No local inference. Text, vision and speech-to-text go only through
  OpenAI, Anthropic, OpenRouter or xAI via AI SDK v7 provider objects
  (never the default gateway). Anthropic has no STT; STT uses OpenAI
  `gpt-transcribe`, xAI Grok STT or OpenRouter
  `/api/v1/audio/transcriptions`.
- D3. An unmodified LGPL ffmpeg build (BtbN `linux64-lgpl`) is allowed only
  as a separate binary inside the capture worker. Every other dependency
  stays MIT, Apache-2.0, BSD, ISC or Unlicense (CLAUDE.md, ADR-014).
- D4. Provider keys are per user, stored in `Setting` (scope USER) encrypted
  with MASTER_KEY, entered through the UI. Never in `.env`, logs, commits,
  fixtures, job rows or progress events.
- D5. No cookies, no paid scraping APIs and no anti-bot bypass by default.
  A blocked platform is a normal typed outcome with a clear next action.
- D6. The capture worker is a required second service for capture, in
  Compose and in single-image deployments (Easypanel/Openship add it as a
  second service). Without it, Product 1 still works and capture answers
  `WORKER_UNAVAILABLE`.
- D7. `CAPTURE_WORKER_TOKEN` is an infrastructure secret in the root `.env`
  (generated by `make dev` like the other secrets) and is given to `web`
  and `capture-worker` only.

## Publication contract (version 2)

- Contract version `1` (target `NOTE`) is unchanged for existing HTTP/MCP
  producers.
- Contract version `2` adds target type `DOCUMENT`, which creates a
  `Transcript` row plus its canonical Markdown in storage, tags and
  summary. It is used internally by capture; it is not exposed as a new
  public HTTP/MCP endpoint in this spec.
- The ingest key for a new capture is `capture:<jobId>` with producer
  `voxen-capture` and external id `<jobId>`; replaying the publish step of
  the same job returns the same document.
- Reprocessing runs a new job with `Job.refreshTranscriptId` set. It
  updates that Transcript in place (same id), first preserving the previous
  canonical text as a `SourceContentVersion` row (skipped when a row with
  the same checksum already exists), and does not use a new ingest key.

## Requirements

### Ubiquitous

- The system shall derive `userId` only from the session for every capture,
  provider and model route; request bodies never carry it.
- The system shall store provider keys encrypted per user and never return
  a stored key to any client; reads expose only provider, a masked suffix
  (last 4 chars), validation status and time.
- The system shall send model requests only to the fixed endpoints of the
  four providers; users cannot set custom base URLs.
- The system shall run interpretation with no tools, no web search and a
  strict output schema; captured content is passed as untrusted data and
  links and images are stripped from the generated summary.
- The system shall keep Product 1 working with no provider key and no
  capture worker: reading, search, MCP, notes and prepared-content
  ingestion never require AI.
- The capture worker shall run as a non-root user with a read-only root
  filesystem, all capabilities dropped, `no-new-privileges`, CPU and memory
  limits, and yt-dlp hardened with `--ignore-config --no-plugin-dirs
--no-remote-components` and `--` before the URL.
- The capture worker shall route every outbound request through the egress
  proxy, shall not publish ports, and shall reject requests without the
  `CAPTURE_WORKER_TOKEN` bearer token.
- Every failure shall carry a stable error code plus a message localized to
  the user's UI language (pt-BR and en) and a suggested action.

### Event-driven

- When the user submits a URL, the system shall check, in this order and
  synchronously, without creating a job:
  1. the URL is http/https, at most 2,048 chars, and not a literal private,
     loopback or link-local address or `localhost` → else `INVALID_URL` or
     `BLOCKED_ADDRESS` (HTTP 400);
  2. a queued or running capture of the same URL exists for the user →
     return that job;
  3. the URL already exists in the user's library → return the existing
     document and offer reprocessing instead of creating a duplicate;
  4. the user has a text role configured → else `AI_NOT_CONFIGURED`
     (HTTP 409) with a link to the AI providers page.
     Then it creates a durable capture job and answers at once with its id.
- When the user uploads a file, the system shall apply check 4 and the size
  and type limits synchronously: types other than audio, video, image, PDF,
  text and Markdown are rejected with `UNSUPPORTED` (HTTP 415) and files
  over 500 MB with `TOO_LARGE` (HTTP 413); otherwise it stores the file and
  creates a capture job.
- When the PWA share target receives a URL, text containing a URL, or
  files, the system shall apply the same submit and upload checks and
  create the matching capture job(s) for the
  signed-in user and redirect to the capture page focused on the job; when
  no session exists, it shall redirect to login and resume afterwards.
- When a capture job runs, the system shall try text first (captions,
  description, post text, page text) and call STT only when no usable text
  exists and the source has audio.
- When neither usable text nor audio nor images exist, the job shall end
  with `NO_TEXT`.
- When interpretation is needed at run time and no text role is configured
  (for example, the key was deleted while the job was queued), the job
  shall end with `AI_NOT_CONFIGURED`.
- When STT is needed and the user has no STT role configured, the job shall
  end with `STT_NOT_CONFIGURED` (pt-BR message "STT não configurado").
- When the captured content has images and little text (below 1,500 chars)
  and a vision role is configured, the system shall describe up to 4 images
  and include the descriptions in the document.
- When interpretation succeeds, the system shall publish one document with
  text, summary, key points, tags, sections/timestamps when available,
  source metadata, capture method, model and cost (contract version 2).
- When the user requests reprocessing of a document, the system shall
  re-run capture and interpretation and update that document in place.
- When the user cancels a queued or running capture, the system shall stop
  it at the next step boundary and mark it `CANCELLED`.
- When the user retries a failed or cancelled capture, the system shall
  reset the same job row to `QUEUED` with `attempt` back to 0 and reuse the
  stored capture artifact when one exists, so only the failed steps run
  again.
- When a provider key is saved or tested, the system shall validate it with
  a cheap authenticated call (models list; OpenRouter `/api/v1/key`) and
  store the validation result.

### State-driven

- While a capture job is running, the system shall publish progress events
  (stage, percent) to the job's realtime channel and persist them for
  replay, so a reconnecting client resumes from the last event.
- While a job holds a lease, the system shall heartbeat it; expired leases
  are reclaimed after restart, up to 3 attempts with backoff for transient
  errors.

### Unwanted behaviour

- If the URL resolves to a private, loopback, link-local or metadata
  address (after DNS or redirects), then the job shall fail with
  `BLOCKED_ADDRESS` and no request shall reach that address.
- If the platform has no extractor and the page yields no text, then the
  job shall fail with `UNSUPPORTED`.
- If the platform requires login, blocks the server IP, rate-limits, or the
  content was removed, then the job shall fail with `LOGIN_REQUIRED`,
  `IP_BLOCKED`, `RATE_LIMITED` or `REMOVED` and suggest uploading the file
  or retrying later.
- If the provider rejects the key or quota, then the job shall fail with
  `LLM_AUTH` or `LLM_QUOTA`; the capture artifact stays stored for retry.
- If the model returns output that fails the schema twice, then the job
  shall fail with `LLM_FAILED`.
- If the capture worker is unreachable, then the job shall be retried with
  backoff and end with `WORKER_UNAVAILABLE` after the last attempt.
- If a step exceeds its time budget (download 15 min, STT 20 min, model
  call 3 min), then the job shall fail with `TIMEOUT`.
- If probed audio is longer than 3 h, then the job shall fail with
  `TOO_LARGE`.

### Optional

- Where a cost estimate exists in the curated catalog, the system shall
  record the estimated cost per job and show it on the job and document.

## Error codes

`INVALID_URL`, `BLOCKED_ADDRESS`, `UNSUPPORTED`, `LOGIN_REQUIRED`,
`IP_BLOCKED`, `RATE_LIMITED`, `REMOVED`, `NO_TEXT`, `TOO_LARGE`,
`STT_NOT_CONFIGURED`, `AI_NOT_CONFIGURED`, `LLM_AUTH`, `LLM_QUOTA`,
`LLM_FAILED`, `WORKER_UNAVAILABLE`, `TIMEOUT`, `CANCELLED`, `UNKNOWN`.

## Out of scope

Local models, embeddings and semantic search, forecasting, cookies and
logged-in capture, paid scraping APIs, channel/playlist subscriptions,
automatic recapture schedules, chat, public HTTP/MCP endpoints for
contract version 2, and MCP tools that start captures.

## Delivery (one PR each)

1. This spec, the spec 215 amendment, CLAUDE.md rules (license exception,
   secrets), ADR-014 and the reviewer roles.
2. Providers: per-user encrypted keys, validation, curated catalog by role,
   AI client, account UI.
3. Capture worker container (yt-dlp, Deno, ffmpeg LGPL, Trafilatura,
   Smokescreen) with Compose service and hardening.
4. Capture pipeline: job runner, STT, vision, interpretation, publication
   (contract v2), progress SSE, cancel/retry/reprocess, capture API.
5. Capture UI, PWA share target, and the user-facing docs (README,
   architecture, security, deploy, MCP) once capture ships.

## Acceptance

- [ ] Fresh install without any provider key: Product 1 works; submitting a
      URL returns `AI_NOT_CONFIGURED` (409) with a link to configure
      providers and creates no job.
- [ ] A saved key is never returned by any API and never appears in logs.
- [ ] Web, X, YouTube (captions) links produce a complete document with
      summary and tags using Anthropic Haiku.
- [ ] Audio-only content with a text role but no STT role ends with
      `STT_NOT_CONFIGURED` ("STT não configurado").
- [ ] Re-submitting the same URL returns the existing job or document.
- [ ] `http://127.0.0.1/`, `http://10.0.0.1/` and `http://169.254.169.254/`
      are rejected at submit; a public URL that redirects to them fails the
      job with `BLOCKED_ADDRESS` (automated tests).
- [ ] Killing the web process mid-capture resumes the job after restart.
- [ ] Sharing a link to the installed PWA creates a capture job.
- [ ] Every new dependency has an allowed license (ffmpeg LGPL and
      Unlicense as the only documented exceptions).
